# Security

To report a security problem in any Kingfish Project repository or service, email [security@kingfish.la](mailto:security@kingfish.la). The [Security Policy](https://kingfish.la/legal/security-policy/) on kingfish.la says what a helpful report includes and what Kingfish commits to once one arrives. It also lists a Signal contact. Before you test anything, read its [scope](https://kingfish.la/legal/security-policy/#scope), [rules of engagement](https://kingfish.la/legal/security-policy/#rules-of-engagement), and [safe harbor](https://kingfish.la/legal/security-policy/#safe-harbor) sections.

## Keep it private

Never describe an unfixed security problem in an issue, a pull request, a discussion, or a commit message in a public repository, because anyone can read them. Keep anything about a source out of them too. If you come across personal information or anything that looks like source material, stop immediately, do not copy, store, or share it, and report what you found, as the rules of engagement require.

## Reporting through GitHub

GitHub's private vulnerability reporting works only in public repositories that have it turned on. In one of those, the **Security and quality** tab offers a **Report a vulnerability** button, and the report goes privately to the repository's maintainers. Report anything else to [security@kingfish.la](mailto:security@kingfish.la), including a problem in a private repository or on kingfish.la. A vulnerability in GitHub itself goes to GitHub, through the [GitHub Security Bug Bounty](https://bounty.github.com/).
